# cidrmerge 0.4.0

This release adopts swift-cidr 0.10.0 and reduces family-projection overhead while
preserving exact coverage and deterministic output.

- Require swift-cidr 0.10.0, bringing its append-based range-to-CIDR summarizer
  into the CLI's existing typed coverage path.
- Build family projections in `CIDRMergeCoverage.ranges` and
  `summarizedNetworks()` with explicit append
  loops. Public return types and deterministic IPv4-first order are unchanged.
- Make the small empty guards available for cross-module inlining, with
  nonempty projection work in internal helpers. Rebuilt ordinary clients can
  avoid the measured empty-call overhead.
- Correct Linux benchmark timing output so GNU `time` supplies the expected
  elapsed, CPU, and peak-memory fields.
- Update dependency notices, consumer checks, and dependency-floor CI for the
  new swift-cidr requirement. The Swift tools minimum remains 6.2.

The complete 57-test suite passed in all 14 normal Debug/Release configurations
on macOS and both Linux architectures, plus a separate dependency-floor run.
Full Swift 6.4.2 Core and production CLI comparisons cover all three platforms;
focused Swift 6.3.3 Core controls cover both Linux architectures.
No selected G/E Core wall-clock p50/p90 or CLI paired elapsed comparison exceeds +5%.
Exact CLI output, coverage and fixed cardinalities are preserved on all three
platforms, and every measured/warmup CLI invocation stays below 512 MiB RSS.

The strict Linux empty-allocation gates pass. The Mac all-observations-zero gate
remains false: both arms have the same single 16-byte event per empty total-allocation histogram,
which a separate fixed-empty-array diagnostic reproduces only with ARC metrics
enabled. Empty allocation p50/p90 values are zero; no primary observations were
removed. Nonempty projections still allocate their output buffers and typed
network arrays.

See the [final qualification](../Benchmarks/Results/2026-11-13-summarization/RESULTS.md#final-follow-up-explicit-loops-and-the-empty-call-fast-path)
for all paired results, sample limits, allocation evidence, exact output checks,
and preserved historical failures. These measurements apply to the recorded
Swift 6.4.2 and 6.3.3 builds. Distributed archives use the Swift 6.2 compatibility
toolchain and receive separate release validation.
